# 方法与实验章节：从材料抽取，与正文对齐

## 1 用途

输入一份真实材料目录（配置 / 日志 / 代码 / 正文），输出：

| 产物 | 内容 |
|-|-|
| `methods_section.md` | 可编辑的章节草稿，按题面六类要素排列，缺的地方写"待作者确认" |
| `params.tsv` | 参数表：要素 / 名称 / 值 / **证据（file:line）** |
| `result.json` | 结构化结果，契约字段平铺到顶层 |

**核心不是填空模板，而是三件事**：从材料抽取要素 → 与正文对齐 → 报出缺口与无来源数值。

## 2 适用条件

| 适合 | 不适合 |
|-|-|
| 有配置 / 日志 / 代码可作事实依据 | 只有一段正文、没有材料可核 |
| 需要判断正文数值是否与配置一致 | 需要生成实验数据 |
| 需要指出六类要素缺哪几类 | 需要改写论文论证逻辑 |

## 2.1 第一步不可跳过：先写 schema.json

只要材料里的键名不确定，就**必须**先让模型读一遍材料，产出 `schema.json`（做法见
`prompts/inspect_materials.md`），再跑脚本。原因是不同论文的键名差异大，脚本按键名匹配会漏。

判据：材料里出现过任何非标准键（`optim.lr`、`train.batch`、`对照组`），就必须先读。
材料是标准键（`lr`、`batch_size`）时可以直接跑，脚本会退回内置规则并在 `uncertainty` 里注明。

## 3 调用

```bash
python run.py --input /input --work /app/work --out /app/output
# 本地示例
python run.py --input examples/case --work work --out output --case-id demo
```

退出码：0 正常（`status` 可能为 `partial`）；1 材料缺失（`blocked`，仍写 `result.json`，另写 `missing_input.md`）。

## 4 流程

| 步 | 模块 | 做什么 |
|-|-|-|
| 0 | 模型（`prompts/inspect_materials.md`） | **先读材料，产出 `schema.json` 键清单**；不同论文键名差异大，按键猜必漏 |
| 1 | `discover()` | 按扩展名与文件名判类型，分桶：配置 / 日志 / 代码 / 正文 / 说明；跳过 `task.md` 与 `case.json`（题面预算与元数据不是材料，`case.json` 只用于 `case_id` 与 `output_contract`） |
| 2 | `extract()` | 按规则表逐行扫，命中即记 `file:line` 证据；同一 (名称,值) 只留首条 |
| 3 | `extract_steps()` | 有代码时从公开函数抽步骤；只有日志/说明时从带时间的动作行抽（`file:line` 仍可回指）；都抽不到才交缺口 |
| 4 | `align()` | 正文是否写到了？正文里出现但材料里没有的数值 → 标"无来源" |
| 5 | `render()` | 按六类要素渲染章节，缺的写"待作者确认" |

规则表在 `run.py` 顶部 `RULES`，只认显式写法（`lr: 0.001`、`torch==2.1.0`），**不倒推数值**。

## 5 六类要素覆盖

题面把章节拆成六类要素，本 Skill 逐条对齐：

| 要素 | 本 Skill | 落在哪 |
|-|-|-|
| 步骤 | 部分 | 优先从代码公开函数名抽；无代码时从日志/说明里的带时间动作行抽（`materials.md:8 10:00 start training`）；不做语义推断 |
| 实验设置 | 做 | `RULES["实验设置"]`：硬件、软件版本、重复次数 |
| 参数 | 做 | `RULES["参数"]`：学习率、批大小、轮数、种子、权重衰减 |
| 数据集 | 做 | `RULES["数据集"]`：名称、版本、划分比例 |
| 对照 | 做 | `RULES["对照"]`：基线对象、对照条件、评价指标、指标值四项各带 `file:line`（基线版本与统计方式同表输出）；哪项抽不到就在该节写"待作者确认" |
| 复现与限制 | 部分 | 给材料清单与待补参数；限制条件需作者补；该节无条件渲染，因此计为已覆盖 |

未覆盖的要素会出现在 `gaps` 里，不静默略过。状态只由"能判却没判过"的项决定：
正文数值对不上、正文漏写、六类要素（含对照）缺料 → `partial`；缺哪一类逐条写进 `gaps`，
对照的四项（基线对象 / 对照条件 / 评价指标 / 指标值）哪项抽不到，只在该节写"待作者确认"，
不编造、不替作者补数。

## 6 输出契约

| 字段 | 含义 |
|-|-|
| `case_id` | 取自 `case.json`；缺失用输入目录名 |
| `status` | `success` / `partial` / `blocked`（`success`=主产物已出且无正文数值问题、六类要素齐全） |
| `六要素覆盖` | 覆盖了哪几类、缺哪几类 |
| `统计` | 材料文件数、抽取参数数、正文一致 / 未写 / 无来源数 |
| `evidence` | 单位 `file:line`，每条参数指明来源 |
| `uncertainty` | 正文里无来源的数值，逐条列出 |
| `gaps` | 正文漏写、无来源数值、六要素缺失 |
| 目标产物 / 事实与来源映射 / 版本与边界 | output_contract 里的题面契约字段，逐字段回显并平铺到 result.json 顶层；未识别字段置 null 并记入 gaps |

## 7 异常处理

| 情况 | 行为 | 状态 |
|-|-|-|
| 找不到配置/日志/代码 | 写 `blocked` 的 `result.json` + `missing_input.md`，退出 1 | `blocked` |
| 配置缺字段 | 不补，进 `gaps` | `partial` |
| 正文数值无来源 | 进 `uncertainty` + `gaps`（日期与时刻等时间戳不算实验数值，已整体跳过） | `partial` |
| 无正文（manuscript） | 跳过对齐，章节按材料落全部抽到的参数，`gaps` 记明"未做正文对齐" | `success` |
| 正文有多份 | 全部读入拼接，不做版本裁定 | `partial`（gaps 注明） |
| 代码无注释/无函数 | 退到日志/说明的带时间动作行；两者都无则步骤为空，进 `gaps` | `partial` |

## 8 限制

- 规则表只覆盖常见深度学习配置键；换领域要改 `RULES`。
- 不做语义理解：函数名不等于步骤描述，只给到可核对的粒度。
- 不判断参数取值是否"合理"，只判断"是否与材料一致"。
- 不产出 Office 文件，因此不需要渲染预览；产物是 Markdown 与 TSV。

## 9 自查

```bash
python run.py --input examples/case --work work --out output
# 期望 stdout：{"ok": true, "status": "success", "params": 8, "missing": 0, "unsourced": 0, "gaps": 2}
```

1. 每个参数都能在 `params.tsv` 里看到 `file:line`。
2. `gaps` 覆盖三条：正文漏写、无来源数值、六要素缺失。
3. `status` 为 `partial` 时，`gaps` 里必有"正文数值/正文未写/六要素缺"之一的实项。
4. 章节里没有材料外的数字（`uncertainty` 为空才敢说没有）。
5. 换一份材料重跑，六要素覆盖应随之变化，而不是恒定输出同一模板。

## 10 预算

脚本本身零模型请求：抽取、对齐、渲染全部是本地正则与字符串比较，不联网、无外部依赖。
唯一一次模型调用在脚本之外：调用方模型读 `element_worksheet.md` 填 `judgments.json`（六类要素归类）。
材料文件数线性增长；10 个文件内为毫秒级。

## 题目对齐（写作09）

| 关注点 | 本 Skill 的机制 | 落在哪 |
|-|-|-|
| 写得全 | 六类要素逐项盘点：步骤、实验设置、参数、数据集与划分、对照、复现与限制 | `result.json` 的 `六要素覆盖` 与 `gaps` |
| 写得准 | 参数值只从配置与日志取，取不到不填，记进 `gaps`，不从段落推 | `params.tsv` 的证据列（文件:行） |
| 做得着 | 输出可执行步骤序列与复现清单（版本、命令、种子） | `methods_section.md` 的步骤段与复现与限制段 |
| 说得住 | 缺口与待确认项单列，限制条件指到具体失效场景 | `result.json` 的 `版本与边界`、`gaps` |

`result.json` 顶层平铺目标产物、事实与来源映射、版本与边界三字段。

## 契约字段映射

| 字段 | 回填内容 | 回显方式 |
|-|-|-|
| 目标产物 | `methods_section.md` 的路径、字符数、行数、六节标题 | full：本次运行算出的值 |
| 事实与来源映射 | 逐条 `{要素, 名称, 值, 来源（文件:行）}` | full：每条参数可回材料 |
| 版本与边界 | `gaps`、无来源数值、六要素缺失 | full：缺口逐条列出 |

`case.json` 给了 `output_contract` 时按它逐字段回显；没给时也照样输出这三项，内容取上表。不存在"契约没给就不回显"的情况。

## 判断层：六类要素归类

脚本出候选与原文锚点，模型判，脚本再核。本节说明本包的判断项。

| 判断项 | 填什么 | 由谁核 |
|-|-|-|
| 这条抽出来的要素属于六类里的哪一类 | 从该条候选里选 1 个：`参数` / `实验设置` / `数据集` / `对照` / `复现`（步骤由 `extract_steps()` 另出一节） | `run.py` 核 `decision` 是否落在该条候选内（`in_candidates`） |
| 凭什么这么归 | 该条证据行（`文件:行` 那一行）里的**原文子串**，不改写 | `run.py` 核 `basis` 是否为证据行原文子串（`basis_verbatim`） |

流程与落点：

1. 规则表只记"这一条可能属于哪几类"（`要素候选`）与规则默认类（`规则判类`），`要素` 一栏留空。
2. 抽完先跑一遍，`--out/element_worksheet.md` 出判断单：`id`（`名称@文件:行#序号`）、取值、证据行、候选。
3. 模型按单填 `<输入目录>/judgments.json`：`{"items":[{"id","decision","basis","filled_by"}]}`，id 必须来自判断单。
4. 再跑同一条命令，`run.py` 读 `judgments.json`，把结论写进 `result.json` 的 `判断层`，并用它算六要素覆盖、章节分节与 `params.tsv`。

`判断层` 字段：

| 键 | 含义 |
|-|-|
| `unit` | 固定 `六类要素归类` |
| `n` / `filled` / `pending` | 待判条数 / 已填条数 / 未填条数 |
| `source` | 读的是哪个 `judgments.json`，读不到就写缺 |
| `who_fills` / `who_checks` | 谁填（调用方模型）、谁核（`run.py`） |
| `items[]` | 每条含 `id`、`item`、`名称`、`对象`、`值`、`证据`、`候选`、`规则判类`、`value`、`basis`、`filled_by`、`status`、`in_candidates`、`basis_verbatim` |
| `exempt` | 不经正则判类的条目：`依赖清单`（文件名判据）、`schema.json` 并入的键（调用方已给类），列出来免得被当成漏判 |

没填的条目 `value` 写 `待判`、`status` 写 `pending`：不计入六要素覆盖，`gaps` 记明条数，**不回落成规则默认类**。
`judgments.json` 缺、坏、id 对不上都不中断主路径：缺的标 pending，多余的 id 不进 items，`skipped_ids` 见代码。
`judgments.json` 与 `case.json`、`task.md` 一样不进材料抽取桶。

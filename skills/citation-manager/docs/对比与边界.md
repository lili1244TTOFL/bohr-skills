# 参考文献与引用管理：与现有方案的边界

题面「创新增益」要求证明创新点相对已有方案的边界与价值。本文件逐项列出：现有做法、本 Skill 的做法、以及做不到的部分。

## 现有方案

| 方案 | 局限 |
|-|-|
| Zotero / EndNote | 管理文献库与导出格式，不判断正文论断与所引文献是否匹配 |
| biber / bibtex | 处理编号与参考文献表，不检论断级引用位置 |
| 期刊模板检查脚本 | 只查格式，不查条目真实性与正文一致性 |

## 本 Skill 的做法

- 句子级分诊判断哪句需要来源，引用插到论断句而非段末
- 插入、删除、调序后重排编号，正文标记与文末列表同步，改动进 changelog
- 条目按判据合并中英文题名与预印本正式版，合并依据写入记录

## 做不到的部分

- 不联网核验 DOI 真实性，只做库内一致性
- 无模型时用内置规则完成分诊与匹配，不停在待办状态
- 跨文件与附录的复杂交叉引用只检测不重排

以上边界都能在包内核对：做不到的项在 `result.json` 的 gaps 或 `SKILL.md` 的限制节里逐条列出。
